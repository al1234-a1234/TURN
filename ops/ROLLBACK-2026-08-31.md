# خطّة الرجوع — تغييرات ٣١ أغسطس ٢٠٢٦

> **غير مُطبَّقة. لا تُنفَّذ إلا بأمرٍ صريحٍ من المالك.**
> كُتبت وقت النشر لا وقت الحادثة — فوقتَ الحادثة لا أحد يكتب خطّةً هادئة.

## ما نُشر في ذلك اليوم

| الترحيل | ماذا فعل | حالة الإنتاج |
|---|---|---|
| `0169_queue_events_and_restore` | جدول `queue_events` + تريغر التسجيل + `restore_queue_entry` + `branch_day_log` + `prune_queue_events` + حرّاس w41–w44 | مطبَّق |

## قاعدةٌ قبل أيّ رجوع

**الرجوع يُنفَّذ بالترتيب العكسيّ للنشر: `0170` ← ثمّ `0171`+`0169` معًا.**
و`0171` **لا يُرجَع وحده أبدًا**: عدّاداته تصف واقعًا أنشأه `0169`. إرجاعه
منفردًا يجعل q20 أحمر فورًا بينما البنية سليمة — أي إنذارٌ كاذبٌ لا إصلاح.

وقبل كلّ رجوع: تحقّق من البوّابة (ساعات الفرعين + `manually_closed` +
الصفوف النشطة). الرجوع تغييرٌ على الإنتاج كالنشر تمامًا.

## ١) الرجوع عن `0170` (قناة التنبيه)

**متى:** إن تبيّن أنّ المرور بـ`notify_telegram` يُفقد إنذارات (تكدّس
`alert_outbox`، أو `status='failed'` متكرّر، أو توقّف وصول الإنذارات).

**الأثر الجانبيّ للرجوع:** تعود المُرسِلات الأربع إلى مهلة ٥ ثوانٍ الافتراضيّة
وإلى الإرسال بلا أثرٍ مكتوب — أي يعود عطل ٣٠ أغسطس. **لا تُرجعه إلا إن كان
البديل أسوأ فعلًا.**

```sql
-- أ) أعِد الأربع إلى net.http_post المباشر.
--    النسخ السابقة محفوظةٌ في git: الملفّ 0170 يحوي التعليق الذي يصف
--    السطر الوحيد المتغيّر في كلٍّ منها (perform public.notify_telegram(x)
--    كان: v_req_id := net.http_post(... بلا timeout_milliseconds ...)).
--    استرجعها من الالتزام السابق لـ0170:
--      git show 06f5f6f:supabase/migrations/  ← ليست فيه؛ النسخ الحيّة
--    الأدقّ: بصمات ما قبل ٠١٧٠ (pg_get_functiondef md5) للمطابقة بعد الرجوع:
--      send_platform_alerts              8731e7edee4a113fb9238f9bda470a9f
--      send_platform_status_digest       c1ee9df7b668c2161f804cfbfa61515e
--      alert_visual_integrity            13cd05d2a13ead901752fe197d0f0264
--      alert_closed_branch_with_waiters  7ff6566cea50250de9a43c2ebac79420

-- ب) انزع الحارس w46 من شبكة الفحوص
do $r$
declare d text; d2 text;
begin
  select pg_get_functiondef(oid) into d
    from pg_proc where proname='run_critical_checks' and pronamespace='public'::regnamespace;
  d2 := regexp_replace(d,
    ',\s*\(''w46_no_unbounded_http_post''.*?\)\)(?=\s*\)\s*select name, pass from checks;)',
    '', 'ns');
  if d2 = d then raise exception 'لم أجد w46 — توقّف'; end if;
  execute d2;
end $r$;
```

**التحقّق بعد الرجوع:** `run_critical_checks` = **٢١٢/٢١٢** (بلا w46)، وبصمات
الأربع تطابق الجدول أعلاه.

## ٢) الرجوع عن `0171` + `0169` معًا (سجلّ اليوم والإرجاع)

**متى:** إن تسبّب تريغر التسجيل في إبطاء الإجلاس، أو ظهر تكرارٌ في
`position` منسوبٌ إلى `restore_queue_entry`، أو تسريبٌ عبر `queue_events`.

**⚠️ فقدُ بيانات:** إسقاط `queue_events` يمحو سجلّ الحركة كلّه نهائيًّا.
إن كان السجلّ مطلوبًا للمراجعة، انسخه أوّلًا:
```sql
create table if not exists backup.queue_events_rollback as
  select * from public.queue_events;
```

**ترتيب الإسقاط ملزم** — `queue_events.customer_id` مفتاحٌ بـ`ON DELETE RESTRICT`:
التريغر أوّلًا، ثمّ الدوالّ، ثمّ الجدول. وبعكسه يفشل الإسقاط أو يعلق.

```sql
begin;

-- أ) أوقف التسجيل أوّلًا حتّى لا يُكتب صفٌّ أثناء الإسقاط
drop trigger if exists trg_log_queue_event on public.waitlist_entries;
drop function if exists public.log_queue_event();

-- ب) الكرون ثمّ الدوالّ
select cron.unschedule('prune-queue-events')
 where exists (select 1 from cron.job where jobname='prune-queue-events');
drop function if exists public.prune_queue_events();
drop function if exists public.branch_day_log(uuid, integer);
drop function if exists public.restore_queue_entry(uuid);

-- ج) الجدول أخيرًا
drop table if exists public.queue_events;

-- د) انزع الحرّاس w41–w44، وأخرج queue_events من branch_rls_everywhere،
--    وأعِد عدّادات q20 إلى ما قبل ٠١٦٩ و٠١٧١ (34→33 · 149→145 · 73→71 · 43→40)
do $r$
declare d text; d2 text;
begin
  select pg_get_functiondef(oid) into d
    from pg_proc where proname='run_critical_checks' and pronamespace='public'::regnamespace;

  d2 := regexp_replace(d, ',\s*\(''w4[1-4]_[a-z_]+''.*?\)\)(?=,\s*\(''(w4[2-4]|q20))', '', 'gns');
  d2 := regexp_replace(d2, ',\s*\(''w44_restore_waitlist_perm''.*?\)\)(?=\s*,\s*\(''q20)', '', 'ns');
  d2 := replace(d2, ',''queue_events'')', ')');
  d2 := replace(d2, 'c.relkind=''r'') = 34', 'c.relkind=''r'') = 33');
  d2 := replace(d2, 'p.prokind=''f'') = 149', 'p.prokind=''f'') = 145');
  d2 := replace(d2, 'from pg_policies where schemaname=''public'') = 73',
                    'from pg_policies where schemaname=''public'') = 71');
  d2 := replace(d2, 'and c.contype=''f'') = 43', 'and c.contype=''f'') = 40');
  if d2 = d then raise exception 'لم يتغيّر شيء — توقّف قبل ترك شبكةٍ نصفيّة'; end if;
  execute d2;
end $r$;

commit;
```

**⚠️ تحذير عن (د):** تعابير `regexp_replace` أعلاه **لم تُختبر** — كُتبت من
شكل الشبكة وقت النشر. نفّذها أوّلًا على `turn-simulation` وتحقّق من
`run_critical_checks` قبل لمس الإنتاج. وإن لم تُطابق، الأسلم يدويًّا:
اقرأ `pg_get_functiondef`، احذف الأسطر الأربعة بعينها، ثمّ `execute`.

**التحقّق بعد الرجوع:** `run_critical_checks` = **٢٠٨/٢٠٨** · q20 أخضر على
33 جدولًا · 145 دالّة · 71 سياسة · 40 مفتاحًا · و`branch_rls_everywhere` أخضر.

## ٣) الرجوع عن الكود (لا القاعدة)

الواجهة تتحمّل غياب القاعدة بهدوء إن رُجع الترحيل وحده: `restoreQueueEntry`
يُرجع رسالة «تعذّر الإرجاع» بدل أن ينهار. لكنّ `branch_day_log` المفقودة
تجعل استعلام لوحة الاستقبال يفشل — **فإن رُجع `0169` فأرجِع الكود معه**:

```bash
git revert --no-edit 848b3bad   # دمج #82 (سجلّ اليوم + الإرجاع)
git revert --no-edit 03c25d66   # دمج #83 (قناة التنبيه) — إن رُجع 0170 أيضًا
git push origin main            # ينشر تلقائيًّا عبر Vercel
```

**الترتيب:** أرجِع الكود **قبل** إسقاط الجدول، لا بعده — وإلا فبين اللحظتين
تفشل لوحة الاستقبال لكلّ موظّفٍ مفتوحةٍ عنده الصفحة.

## ٤) ما لا يُرجَع

- **`0165`/`0166`** (اليوم التشغيليّ) و**`0168`** (الترقيم لكلّ قسم): سابقةٌ
  لهذا اليوم، ولا علاقة لها بما نُشر فيه.
- **`0139`–`0145`** (توثيق الترحيلات اليتيمة): ملفّاتُ توثيقٍ لواقعٍ قائم،
  لم تُطبَّق على القاعدة أصلًا — فلا شيء فيها يُرجَع.
