# دليل مدير المنصّة — تشغيل «دور» بنفسك

> هذا دليلك أنت (المؤسس)، لا دليل المطاعم — ذاك في `OWNER-GUIDE.md`.
> كل مهمة هنا تنجزها بلا مهندس. ما يحتاج مهندسًا مكتوب صراحة «جلسة هندسية».

---

## ١) خزنة الشركة — أول شيء تسويه، ورقة واحدة

اكتب بخط يدك (أو ملف مشفَّر خارج كل هذه الحسابات) واحفظها بمكان آمن:

```
البريد الجامع: ____________  (وبريد الاسترداد له: ____________)
GitHub:   المستخدم/المستودع + طريقة الدخول
Supabase: البريد + المشروع (ref: nkdfxmjuigslmangzuua)
Vercel:   البريد + الفريق + المشروع
النطاق:   المسجِّل + تاريخ الانتهاء: ____________
مفتاح النسخ (BACKUP_PASSPHRASE): ____________
مفتاح الإشعارات الخاص (VAPID_PRIVATE_KEY): ____________
  ← انسخه من Vercel ← المشروع ← Settings ← Environment Variables.
  نسخته الوحيدة هناك — ضياعه يعني موت إشعارات كل العملاء المشتركين.
حساب الراصد الخارجي (UptimeRobot): ____________
```

فعّل **التحقق الثنائي** على الخمسة كلها. ضياع هذه الورقة أخطر من أي عطل.

---

## ٢) لوحة الصباح — ٩٠ ثانية بجوالك

1. **الراصد الخارجي أخضر؟** (تنبيهه يصلك أصلًا لو احمرّ).
   *(عند إعداده أنشئ راصدَين: واحد على حالة `/api/health`، وثانٍ «كلمة
   مفتاحية» ينبّه إذا ظهرت `"cron_fresh":false` — هذا يكشف موت الوظائف
   الليلية خلال ٤٨ ساعة بلا أي وكيل.)*
2. **افتح** `/api/health` — تشوف `{"ok":true,...}`؟ تمام.
3. **بريدك**: لا رسالة فشل من GitHub Actions (النسخة الليلية)؟ تمام.

أخضر × ٣ = يومك سليم، سكّر الجوال.

---

## ٣) إضافة مطعم جديد — من الصفر للتشغيل (ربع ساعة)

1. **أنشئ المطعم**: حاليًّا عبر جلسة وكيل/مهندس بسطر SQL واحد (اسم + slug + فرع).
   *(لوحة إدارة منصّة ذاتية = فكرة مؤجلة في موقف الأفكار بالخطة).*
2. **أنشئ حساب المالك** بنفس الجلسة، وسلّمه: رابط `/partners` + معرّف المطعم + اسم المستخدم + الرمز.
3. **المالك يكمل بنفسه** (دليله `OWNER-GUIDE.md` — اطبعه له): قالب الباركود،
   الملصقات، الولاء والطبقات، حسابات فريقه من **لوحة التحكم ← الفريق**.
4. تحقّق معه بمسح تجريبي واحد واعتماد هدية واحدة عند الكاشير. انتهى.

## ٤) مشاكل الرموز والدخول

| الحالة | الحل | من يقدر |
|---|---|---|
| موظف استقبال نسي رمزه | **لوحة التحكم ← الفريق ← إعادة ضبط** | مالك المطعم بنفسه |
| مالك (أو أنت كأدمِن) يريد **تغيير** كلمة مروره وهو داخل | **🔑 حسابي** في القائمة الجانبية (أو `/account`) | بنفسه، بلا أي جلسة إدارة |
| مالك مطعم **نسي** رمزه تمامًا (خارج الحساب) | إعادة ضبط من إدارة المنصّة (`/account` يحتاج تسجيل دخول أولًا فلا يفيد هنا) | أنت (جلسة وكيل/مهندس، دقيقتان) |
| مطعم يشكو «العميل ما تجيه هديته» | اسأله: هل ضغط **حفظ** في «ماذا يفعل الباركود؟» — القوالب لا تعمل قبل حفظه | أنت بالهاتف |
| مطعم كبير يُرفض عملاؤه وقت الذروة (rate_limited) | **لوحة التحكم ← امسح خذ هديتك ← أقصى مسحات بالساعة** — ارفعه | مالك المطعم بنفسه |

## ٥) عند عطل — شجرة القرار

```
الراصد أحمر / شكاوى؟
├─ /api/health يفتح ويقول ok:true؟
│   └─ نعم ← المشكلة في صفحة/ميزة محددة لا في المنصة:
│        جرّبها بنفسك، ولو تأكدت → جلسة هندسية (أو تراجع نشر، تحت)
├─ /api/health يفتح ويقول ok:false أو db:fail؟
│   └─ قاعدة البيانات: افتح status.supabase.com
│        عطل عندهم ← انتظر (دقائق–ساعات) وبلّغ مطاعمك
│        ما فيه عطل عندهم ← افتح لوحة Supabase: هل المشروع Paused
│        (فاتورة/خمول)؟ فعّله/ادفع — يرجع خلال دقائق
└─ /api/health لا يفتح إطلاقًا؟
    └─ افتح vercel-status.com — عطل عندهم ← انتظر.
       ما فيه ← لوحة Vercel: آخر نشر أحمر؟ ← تراجع نشر (تحت)
```

**التراجع عن نشر خرب (بلا مهندس):** لوحة Vercel ← المشروع ← Deployments ←
آخر نشر أخضر قديم ← ⋯ ← **Promote to Production**. ثوانٍ ويرجع كل شيء كما كان.

## ٦) النسخ الاحتياطي — كيف تديره

- **يعمل وحده يوميًّا** (٤:٣٠ فجرًا بتوقيت الرياض) في GitHub ← تبويب **Actions**.
- **فشل؟** يصلك بريد تلقائي من GitHub. افتح الـAction واقرأ السطر الأحمر —
  غالبًا سرّ منتهي (غيّرت كلمة سر القاعدة؟ حدّث `SUPABASE_DB_URL` في
  Settings ← Secrets ← Actions).
- **تنزيل نسخة**: تبويب Actions ← آخر تشغيلة خضراء ← Artifacts.
- **فكّها** (على أي جهاز فيه openssl):
  `openssl enc -d -aes-256-cbc -pbkdf2 -in turn-backup-*.tar.enc -pass pass:'مفتاحك' | tar -x`
- **تمرين الاستعادة الربع سنوي**: جلسة هندسية تتبع `RESTORE.md` على مشروع
  Supabase تجريبي مجاني — الهدف إثبات أن النسخة تُحيي المنصة فعلًا.

## ٧) متى تحتاج «جلسة هندسية» (وكيل Claude أو مهندس)؟

إضافة مطعم، إعادة رمز مالك، عطل مؤكد في ميزة، تمرين الاستعادة، تحديث
الاعتماديات الربع سنوي، وأي شيء في `PLAN.md` تحت المرحلتين ب/ج.

**كيف تفتح جلسة تكمل من حيث انتهينا:** المستودع نفسه هو الذاكرة — أي جلسة
جديدة اطلب منها أول شيء: *«اقرأ docs/PLAN.md و CLAUDE.md ثم نفّذ كذا»*.
كل القرارات والأسباب هناك؛ ما تحتاج تشرح التاريخ.

## ٨) الإيقاع الدوري (من سجل المخاطر — `RISKS.md`)

| متى | ماذا |
|---|---|
| يوميًّا | لوحة الصباح (٩٠ ثانية) |

## ٩) لو اختفى الوكيل (أو أنثروبيك كلها) — الحقيقة والخطة

**لا شيء من المنصة يعمل على أنثروبيك.** يوم اختفائها: الموقع والطوابير
والمسح والكرونات والنسخ والراصد كلها تستمر كأن شيئًا لم يكن. الذي يتوقف
فقط: الفحص الذكي اليومي وقدرتك على سؤال الوكيل.

**بديلك جاهز بتصميم متعمّد:** المستودع تقنيات قياسية (Next.js + Postgres)
وكل قرار وسببه موثّق. أي مطوّر مستقل («مستقل»، «بحر» — ١٠٠–٣٠٠ ر.س/ساعة،
ساعات معدودة شهريًّا) أو أي أداة AI برمجية أخرى: أعطه رابط المستودع وقل
«اقرأ docs/PLAN.md ثم نفّذ كذا» — يمسك الخيط خلال ساعة.

**شرط صحة هذا كله:** حساباتك الخمسة بيدك، وخزنتك معبّأة، والوصايا أدناه.

## ١٠) وصايا «لا تفعلها أبدًا» — للمالك غير التقني

1. **رابط اتصال القاعدة لا يُعطى لأحد** — لا مهندس ولا «دعم» ولا محادثة.
   مكانه: سرّ GitHub + الخزنة فقط. من يملكه يملك كل شيء متجاوزًا كل حماية.
2. **الاحتيال (Phishing) هو الطريقة رقم ١ لسرقة المنصات**: بريد يدّعي أنه
   من Supabase/Vercel/GitHub ويطلب دخولك؟ لا تضغط رابط البريد — افتح
   الموقع بنفسك من المتصفح. الدعم الحقيقي لا يطلب كلمة سر أبدًا.
3. **SQL Editor**: لا تنفّذ ما لا تفهمه حرفيًّا — ولو أرسله «خبير».
4. **RLS لا يُعطَّل** على أي جدول مهما كان المبرر.
5. **متغيرات بيئة Vercel لا تُحذف** — فيها مفتاح الإشعارات، لا نسخة له
   غير خزنتك.
6. **القراءة آمنة دائمًا، التغيير عبر هذا الدليل فقط** — وما ليس فيه
   فهو «جلسة هندسية».

## ١١) منهج المالك — طيّار يقرأ العدادات لا مصنع طائرات

- **الأسبوع الأول (٢٠ دق/يوم، قراءة فقط):** جولة Table Editor (جداولك
  بعينك) ← Vercel Deployments (اعرف مكان Promote ليوم الشدة) ←
  GitHub Actions (سجل النسخ) ← اقرأ `RISKS` ثم هذا الدليل ثم `BLUEPRINT`.
- **الشهر الأول:** فحص الصباح عادة راسخة · فكّ نسخة احتياطية مرة على
  جهازك (§٦) · احضر جلسة إضافة مطعم وشاهد الخطوات.
- **كل ٣ أشهر:** اشهد تمرين الاستعادة وافهمه — لا تنفّذه.
- **ما لا تتعلمه: البرمجة.** تحتاج فقط معرفة متى تستدعي من يبرمج وماذا
  تطلب منه — وكلاهما في هذه الأدلة.
